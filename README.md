## Основные преимущества по сравнению с Jarvis

1. Гексогональная архитектура:
- деление на полностью независимый **доменный модуль**, который содержит бизнес-логику системы, страховых продуктов.
Это даёт возможность изолированного тестирования бизнес-логики приложения, а также возможность переноса
системы на другие платформы на базе других фрейморков.
- деление на **модуль платформы** на базе **Spring Boot**, который содержит адаптивный слой и основной технологический стек.
Благодаря такому делению, можно не беспокоится что правки в этом модуле заденут бизнес-логику, следовательно можно
оптимизировать производительность, добавлять новые тех. фичи, например кэширование, логирование, AOP, реактивный-стек, AI-модуль() и т.п.,
причем все фичи идут из коробки **Spring Boot**)
- Благодаря такому разделению, несколько разработчиков могут независимо вести разработку различных модулей и частей системы,
без риска сломать работу какого-либо разрабатываемого модуля другого коллеги-разработчика.

2. Скорость запуска приложения даже на начальном этапе разработки в несколько раз быстрее, что дает прямую возможность
использования модулей в качестве микросервисов.
3. Готовый веб-движок, что избавляет от необходимости поддерживать свой собственный
4. Удобная и глубокая система конфигурирования. От настроек пула потоков для обработки запросов веб-сервера, 
до настроек страхового продукта, без пересборки и деплоя системы.
Пример:
```yaml
server:
  port: 8081

products:
  dms:

      name: sber
      enable: true
      url: https://payment.sberbank.ru/partner/123
```
